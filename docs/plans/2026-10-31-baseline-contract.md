# B0 필수 조건·결정적 기본순의 첫 실행 계약

## 범위·선행 조건

- 기준 main: `dba34e515c81db26a0de0e4640af88aaf13bb73f`.
- DATA-AND-MODEL-PLAN의 B0, C03·DAT03·AI01의 독립 선행 증가분이다.
- 사용자/로그·원천 수집·Backend 상품 특성 API를 기다리지 않고, 호출자가 명시한 카탈로그로
  작동하는 내부 계산 계약을 먼저 제공한다. 상품 사실·저장/권한·이벤트는 Backend가 소유한다.
- B1 fit/모델 학습·서비스 카탈로그 감사·관련성 평가·Backend/Frontend 통합은 미완료다.
  신규 API 구현을 필수 20개 기능의 통합 완료나 기존 모델의 결함/성능 개선으로 집계하지 않는다.

## 결정

- `POST /v1/recommendations/baseline`, 최대 1000개 카탈로그와 명시 조건/제외·limit을 받는다.
- 필수 조건을 먼저 적용한 뒤 ID 오름차순을 사용한다. 인기/선호 데이터가 없으므로 점수를
  꾸미거나 입력 목록 순서를 인기순으로 간주하지 않는다.
- 판매 상태는 필수 boolean, 미확인 특성은 null이다. 조건이 해당 특성을 요구하면 제외하며
  unknown을 0이나 추정값으로 채우지 않는다. 후보 부족은 빈 결과/명시 사유로 반환한다.
- 중복 ID/불명확한 타입/불가능한 범위는 422로 거절한다. 512 KiB 원문 제한은 ASGI 수신 중
  누적으로 적용하고 입력 원문을 검증 오류에 재노출하지 않는다.
- 계약 문서는 Recommendation `docs/BASELINE-API.md`, 실행 OpenAPI가 정본이다.
  조정자에게 프로토콜을 보고하고 Backend의 ApiResponse와 분리된 내부 JSON 계약으로 합의했다.
- Pydantic은 FastAPI의 기존 잠금 버전을 유지하면서 직접 의존성으로 명시했다. 새 모델/데이터
  라이브러리를 도입하거나 수집·다운로드하지 않았다.

## 실제 검증·증빙

- 직접 작성한 가상 입력에서 주종·가격·도수·제외·판매 상태의 교집합과 양 끝 경계를 확인한다.
  unknown·0, 입력 순열·limit 순서, 빈 후보, 중복 ID·형식/상한·비유한 수치·크기 경계를 포함한다.
- 최종 `./scripts/check.sh`에서 저장소 검사·locked 설치·Ruff 검사/포맷·pytest 41개와
  새 sdist/wheel·runtime-only 격리 설치·실제 HTTP health/B0/OpenAPI·중복 ID 422를 통과했다.
  Starlette/HTTPX TestClient의 기존 사용 중단 경고 1개는 남아 있으며 테스트 실패가 아니다.
- README Python 발췌를 실제 함수의 AST 범위와 비교해 일치함을 확인했다.
  마지막 문서 검증 기록 갱신 후 저장소·공백·포맷 검사를 다시 확인했다.
- 초기 sandbox의 UV cache/DNS 제한은 export 및 승인된 검증 실행으로 해결했다.
  이 실행 환경 제한을 제품 장애·성능 개선으로 기록하지 않는다.
- 격리 배포 smoke는 새 sdist/wheel·runtime-only 설치·checkout 밖 python -I·OS 동적 포트의
  health/OpenAPI에 추가로 실제 추천 POST·중복 ID 422를 확인한다.
- 테스트 fixture는 외부 데이터/사용자 선호가 아니다. 실제 관련성 지표·모델 품질·성능 기준값은
  이번 범위에서 측정하지 않았으며 숫자를 만들지 않는다.

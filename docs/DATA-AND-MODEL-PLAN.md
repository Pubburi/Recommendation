# 주류 데이터·추천 모델·평가 계획

이 문서는 **Recommendation 레포가 소유하는 데이터 원천·수집/정제·카탈로그·특성·추천 모델·학습·평가의 정본**이다.
추천 모델 코드·설계·실험·테스트·결과는 이 레포에 관리한다. 다른 영역의 코드·설계·검증은 해당 레포가 소유한다.
현재 채팅과 연결된 비공개 승인 기획의 최신 지시를 함께 적용한다.

2026-11-03 승인 변경에 따라 **R01–R08과 F01–F12의 전체 20개 MVP 기능을 2026-12-31
Asia/Seoul까지 구현·연결하고 필수 검증을 완료한다.** P1·P2는 구현 순서이며 범위 제외가 아니다.
2027-01-01부터 추가 개선·최적화를 진행하고 최종 기한은 2027-02-05 한국 시간까지 유지한다.
2027-02-06 00:00 Asia/Seoul부터 새 구현·커밋·병합을 중단하고 미완료·검증·PR을 인계한다.
DAT01–DAT04는 기존 기능과 AI01–04의 기술 작업이므로 별도 기능으로 중복 집계하지 않는다.
기존 완료 기준은 유지하며 날짜 변경이나 부분 제공자/fixture 구현만으로 완료 상태를 올리지 않는다.

서비스는 **비상업 사이드 프로젝트**이며 **외부 사용자·행동 데이터 축적이 없다**.
명시 취향·상품 맥락과 카탈로그만으로 모델을 개발하고 사용자 모집·미래 로그·외부 평가자 확보를 기다리지 않는다.
원천·수집 범위·정제/특성·모델·튜닝·평가·채택은 담당 에이전트가 공식 출처와 재현 실험에 근거해 자율 결정한다.
조건에 맞지 않는 원천이나 알고리즘은 대안으로 바꾸고 실제 차단만 보고한다. 상업적 이용 전 협의 조건만으로
현재 비상업 이용을 차단하지 않으며 공개 데모·학습·원본 재배포·이미지/원문은 항목별 조건을 확인한다.
향후 상업적 이용으로 전환하면 이용 범위를 다시 검토한다.

AWS 연결 지시 전까지 로컬에서 작업한다. 챗봇·모바일 구현·실제 결제/배송은 범위 밖이며 모바일용 공통 API 계약만
유지한다. 기존 비용·계정 권한·외부 연락 경계, 소유권 lease, 최신 head의 필수 CI·Codex 리뷰·관련 검증과
미해결 지적 없음 확인 후 Squash merge, main CI·ff-only 동기화와 병합 브랜치 삭제 기준을 유지한다.

## 레포 소유와 연동 경계

| 영역 | 소유 범위 |
|---|---|
| Recommendation | 허용 원천의 수집·정제 카탈로그, 데이터 품질·특성 산출·버전, 추천 점수/이유·학습·평가·실험/테스트 |
| Backend | 업무 MySQL의 상품 원본·인증/세션·주문·이벤트·공통 API, OpenSearch 색인 동기화·검색 API·장애 대체 검색 |
| Frontend | 명시 취향·검색/추천·피드백 화면, 상태·요청·오류·사용자 흐름 검증 |
| 공동 계약 | 상품/취향/맥락·필수/제외 조건·응답 이유·오류·버전 필드는 담당 간 합의하고 각 레포의 계약/테스트로 보존 |

Recommendation의 수집·정제 카탈로그와 특성은 모델 입력이며 Backend의 업무 데이터 소유권을 대체하지 않는다.
Backend가 전달한 유효 후보 안에서 점수·이유를 계산하고 필수 조건을 벗어난 상품을 추가하지 않는다.
데이터·모델·평가 변경의 정본은 이 문서와 이 레포의 구현/테스트이며 Backend 문서를 읽어야만 판단할 수 있게 두지 않는다.

검색 S01–S05와 검색 API·색인·동기화 상세는 Backend가 소유한다.
현재 [Backend 연동 기준](https://github.com/Pubburi/Backend/blob/main/docs/DELIVERY-PLAN.md)을 참고하고,
검색 상세는 Backend의 `docs/SEARCH-PLAN.md`에서 관리한다. 추천 준비·장애 계약은 GET /health의
프로세스 가용성과 구분하고 Backend의 timeout/fallback 및 최신 가격·판매 상태/제외 재확인과 맞춘다.

## 데이터 수집 원칙

우선순위는 **이용 범위를 확인한 API/다운로드 → 제공 허락을 받은 자료 → 직접 작성/측정한 자료**다.
웹에 공개됐거나 robots.txt가 허용한다는 사실만으로 재사용·학습·재배포 권리를 승인하지 않는다.
약관·라이선스·추가 유의사항·호출 제한을 함께 확인한다. 로그인/차단 우회와 무단 대량 수집,
상점/블로그 후기·작성자 계정 수집을 기본 전략으로 삼지 않는다. 외부 문의 발송은 별도 사용자 지시를 따른다.

원천마다 URL·제공자·확인일·버전/해시·허용 목적(표시/검색색인/학습/공개 재배포)·출처 표시·
변경 표시·이미지 조건·요청량·삭제/수정 대응을 기록한다. 충돌/미확인은 보류하며 다음 수집원으로 우회한다.
API 키는 로컬 환경변수로 관리한다. 원본 데이터·모델·권한 없는 이미지·원문·실사용 로그는 Git에 올리지 않는다.
재현 가능한 수집 명령·명세·권리 기록과 직접 만든 작은 테스트 fixture만 추적한다.
기존 시드·정적 이미지 역시 출처/사용 허락이 확인됐다고 가정하지 않고 감사한다.

aT의 여러 도수·용량과 제품 변형은 같은 SKU인지 확인한다. 행 수를 고유 상품 수로 취급하지 않는다.
가격 출처가 없으면 실제 판매가로 만들지 않고 별도 시연 가격임을 표시한다. 맛·향은 허용 자료나
직접 평가의 기준/평가자를 기록하고, 미확인 값은 unknown으로 보존한다. 상품명·도수·LLM 추정으로
관능 점수를 만들어 관측값처럼 쓰지 않는다. 이미지·소개 문장·리뷰는 상품 사실 정보와 권리를 따로 판단한다.
Open Food Facts 등 별도 DB/이미지 라이선스 의무가 있는 원천은 기본 원천으로 승인하지 않는다.
2026-11-01의 [OFF 공식 API 문서](https://openfoodfacts.github.io/openfoodfacts-server/api/) 재검토는
ODbL/DBCL·이미지 별도 조건과 API 사용 전 usage form 안내를 확인한 단계다. CC0와 동일하게
취급하지 않았고 폼/계정/외부 연락·실제 데이터 수집을 진행하지 않아 기존 채택 상태는 유지한다.

## 추천 모델을 개발하는 순서

**AI03은 사용자 없이 가능한 카탈로그 기반 학습·비교로 확정한다.** 협업 필터링·행동 기반
선호 학습은 현재 개발의 필수 경로로 채택하지 않는다. 데이터 권리·필드/규모 감사 뒤 다음 모델을 비교한다.

| 구분 | 학습·점수 | 비교·채택 기준 |
|---|---|---|
| B0 기본 기준선 | 필수/제외 조건을 적용한 결정적 기본순 | 신규 취향·빈 데이터·장애에서 재현 가능한 기본 동작. 시드 order_count를 실제 인기 통계로 해석하지 않음 |
| B1 기본 서비스 모델 | 검수 주종/태그·허용된 텍스트의 TF-IDF vocabulary/IDF와 수치 특성 변환을 카탈로그에 실제 fit. 입력 취향·선택 상품과 유사도 계산 | 특성/누락/스케일/가중치 근거를 버전 관리. 필수/제외 조건을 먼저 적용하고 추천 이유는 실제 사용 특성과 일치 |
| M1 표현 학습 후보 | 차원·제품 다양성이 충분하면 TF-IDF + TruncatedSVD 등 비지도 카탈로그 표현 학습을 실제 비교 | 표본/차원/rank를 확인해 구성 선택. 크기/정보 보존/관련성/지연을 B1과 비교하고 유용할 때만 운영 채택. 작은 데이터에 억지로 적용하지 않음 |
| D1 심층 신경망 후보 | 검수 상품군 TF-IDF를 입력으로 다층 오토인코더를 학습하고 병목 임베딩으로 유사 후보를 검색 | 고정 분할에서 TF-IDF와 비교. 지원 범위·독립 관련성·제약·근거·실패 대체와 지연을 확인한 뒤 채택 여부 결정. [첫 학습·비교](SOURCE-FAMILY-COHORT.md#다층-신경망-후보) |

TF-IDF의 학습은 카탈로그의 어휘/빈도 특성을 맞추는 것이며 사용자 선호 학습이 아니다.
검색엔진 색인 생성과도 구분한다. B1의 실제 fit·기준선 비교·보고서는 필수다. M1은 적합성
검토와 근거 있는 채택/미채택을 요구하며, 복잡한 모델의 운영 채택 자체를 성공 기준으로 두지 않는다.
유효한 실험 없이 문서상의 선택만으로 학습 완료 처리하지 않는다. 표본이 부족하면 허용 카탈로그를
확대하거나 표현을 단순화해 실행하고 실제 권리/데이터 차단을 기록한다.

D1은 2026-11-06 사용자 지시에 따라 AI03에서 첫 오프라인 학습과 기준선 비교를 먼저 실행했다.
후보의 운영 채택과 확대 튜닝에는 별도 검증 기준과 기존 일정이 적용된다.
다음 단계는 권리와 업무 ID를 확인한 더 다양한
카탈로그에서 상품군별로 학습·검증·최종 평가를 분리하고, 모델 입력을 그대로 정답으로 복제하지 않은
관련성 명세로 비교하는 것이다. 모델이 바뀌더라도 업무 필수 조건과 사실에 근거한 이유, B0 대체 동작을
같은 인수 과정에서 확인한다.

[고정 M1 표현 비교](measurements/2026-11-03-source-representation-comparison.md)는 기존 승인11상품군의5fit×7/
rank5·6transform과 baseline 전체를 유지한 채 TF-IDF +2차원 TruncatedSVD를 실제 실행했다.
학습 에너지51.10%·재구성 상대 오차0.6993·설명분산26.72%와 변환 영벡터5/6 불변, 양성1질의/
전체6의 같은 사실 지표를 분리했다. 정보 손실·OOV 지원 불변/독립 품질 근거 부족으로 이번 후보는
운영 미채택하며 변환 질의로 차원을 튜닝하지 않았다. source 상품군의 적합성 실험으로서 신규
업무 매핑/서비스 SKU fit·서비스 품질·전체 AI03 완료를 뜻하지 않는다. [동결/원값](measurements/2026-11-03-source-representation-comparison.md)을 보존한다.

## 사용자 없는 기능·평가

- R02는 현재 입력한 명시 취향으로 즉시 개인화한다. R03은 상품 특성 유사도, R04는 실제 근거,
  R05는 입력 피드백의 순위/제외 반영, R07은 장바구니/데모 주문의 상품 특성·검수 규칙,
  R08은 유사성과 속성 다양성을 함께 고려한다. 모든 R/F 기능은 시연 계정으로 저장·권한·복구까지 검증한다.
- 연관 후보를 함께 많이 구매한 통계로 표시하지 않는다. 실제 선호 데이터 없이 인기·CTR·전환율·
  사람의 만족도·취향 적중률을 성과로 쓰지 않는다. 시연 가격과 기록의 성격을 유지한다.
- 프로필/장바구니/찜/평점/관심 없음의 시나리오 입력과 합성 행동은 선언형 기능 시험 조건이다.
  실제 고객을 대체한 선호 정답이 아니다. 학습을 위해 가짜 클릭/평점을 대량 생성할 필요가 없다.
  계정 식별/개인정보·권한·보관/삭제 계약은 기능상 유지하되 로그 축적을 기다리지 않는다.

평가는 세 층을 구분한다.

1. **필수 기능·정합성:** 독립 검사기로 가격/도수/주종 조건·제외·중복·링크·추천 이유·누락/상충 조건·
   신규 프로필·장애 fallback을 검증한다. 필수 조건 위반과 제외 상품 재노출은 없어야 한다.
2. **카탈로그 관련성:** 튜닝 전에 고정한 질의/프로필 명세와 확인 가능한 상품 사실로 관련성을 평가한다.
   추천 점수 함수로 정답을 다시 만들지 않는다. AI 초안의 라벨도 출처 사실과 추정을 구분해 검수하고
   확인 불가능한 맛/향을 정답에서 제외한다. 독립 관련성 라벨이 있을 때만 Recall/NDCG를 산출하고
   '카탈로그 시나리오 관련성'으로 명명한다. 단순 필터 통과율은 조건 검증이며 개인 취향 정답이 아니다.
3. **표현·운영:** 카탈로그 커버리지·속성 다양성·누락/변형 안정성과 고정 조건의 지연/메모리·재현성을 비교한다.
   재구성 오차/설명분산은 표현 정보 보존 지표이며 사람의 선호 품질로 환산하지 않는다.

**고정 카탈로그 평가**는 알려진 전체 카탈로그를 표현/색인에 사용했는지 밝히고 개발/검증/최종
시나리오를 분리해 최종 명세를 고정한다. **신규 상품 일반화**는 동일 제품/용량·도수 변형을
그룹으로 묶어 학습/검증/최종 평가를 나누고 어휘·스케일·차원 축소를 학습 부분에만 fit한다.
두 결과를 혼용하지 않는다. 실제 시계열/사용자 데이터가 없는 상황에 시간·사용자 분리를 꾸미지 않는다.
동일 후보·필터·K·카탈로그 버전으로 B0/B1/적합한 M1을 비교하고 원값·실패·분리·한계·선택 근거를 남긴다.
관련성 라벨이 없으면 그 지표는 미산출 사유와 대체 검증을 기록하며 AI03 전체를 사용자 부재로 대기시키지 않는다.
UCI 품질 예측은 선택적 별도 실험이며 카탈로그 추천 학습/평가 완료를 대신하지 않는다.
